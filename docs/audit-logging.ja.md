# 監査ログ

Xylem は `@hono/structured-logger` と `pino` を使い、構造化 JSON ログを出力します。このガイドは [app.ts](../src/app.ts)、[ミドルウェア](../src/middlewares)、[監査用ヘルパー](../src/logging)の現在の実装を説明します。

## 対象範囲と共通フィールド

監査ミドルウェアは `/api/upload`、`/api/normalize`、`/api/gpx/*`、`/s/*` に登録されています。ヘルスチェックと通常の静的ファイルへのリクエストは、この登録範囲に含まれません。共有ページのキャッシュにヒットした場合もリクエスト・レスポンスのイベントは出力しますが、上流からのデータ取得は行いません。

リクエストに紐づくフィールドは `service`、`request_id`、`method`、`path` で、取得できた場合は `client_ip` と User-Agent 関連フィールドも含みます。イベントには `timestamp`、`event`、`result` があり、`status`、`elapsed_ms`、`gpx_id`、失敗の詳細が付く場合があります。`request_received` はミドルウェアに到達したことを示し、検証成功を意味しません。`response_sent` はレスポンス・エラーフックで出力され、クライアントへの到達を確認するものではありません。

成功イベントは `info`、失敗イベントは `error` で出力し、`LOG_LEVEL` による出力制限を受けます。HTTP ステータスの判定用ヘルパーは 400 未満を成功とします。取得処理ではより厳しく判定し、上流の 200 応答から取得した正規化データの検証に成功した場合だけ、取得成功イベントを出力します。イベントの `status` は最終的なクライアント応答ではなく上流の応答を示す場合があり、上流応答がない場合にはローカルで対応付けたステータスとなることもあります。途中のイベントが成功しても、操作全体の成功を意味しません。

## リクエスト ID

Hono の `requestId({ headerName: "" })` はリクエストごとにサーバー側で ID を生成し、クライアントからの `X-Request-Id` を採用しません。ID は監査レコードの `request_id` に設定され、[サービスクライアント](../src/services/anemochore.ts)から Anemochore に `X-Request-Id` として送信されます。Xylem はレスポンスヘッダーには追加しません。上流サービスがこのヘッダーを記録する場合にログの対応付けに使えますが、これだけでシステム全体のログ記録が保証されるわけではありません。

## クライアント IP と設定

| 変数 | 既定値 | 動作 |
| --- | --- | --- |
| `LOG_LEVEL` | `info` | Pino の出力閾値。`trace`、`debug`、`info`、`warn`、`error`、`fatal`、`silent` を指定できます。 |
| `XYLEM_TRUST_PROXY` | `false` | `true` または `1` で転送 IP の処理を有効化し、`false` または `0` で無効化します。 |
| `XYLEM_TRUSTED_CLIENT_IP_HEADER` | `X-Forwarded-For` | 転送 IP の処理が有効な場合に使用するヘッダー。 |

プロキシの信頼設定が無効な場合、転送ヘッダーは無視します。有効な場合は、ヘッダーをカンマで区切った最初の空でない値が有効な IP アドレスであれば使用します。接続元プロキシのアドレス許可リスト照合や、信頼できるホップの連鎖の評価は行いません。信頼できないクライアントからの直接アクセスを防ぎ、信頼できるプロキシが指定ヘッダーの先頭値を含めて管理する環境でのみ有効にしてください。そうでなければ、クライアントがログに記録する IP アドレスを偽装できます。

有効な転送アドレスが得られない場合、サーバーアダプターから有効な直接接続アドレスを取得できれば使用し、できなければ `client_ip` を省略します。取得できたクライアント IP は Anemochore にも `X-Client-IP` として送信します。

これらの変数はアプリケーションのプロセスに渡す必要があります。付属の [compose.yml](../compose.yml) は現時点ではログ関連変数を渡さないため、ホストのシェルで設定するだけではサービスに反映されません。

## イベント

| イベント | 出力元 | 意味 |
| --- | --- | --- |
| `request_received` | ミドルウェア | 監査対象リクエストが Xylem に到達しました。 |
| `response_sent` | ミドルウェア | 監査対象リクエストのレスポンス・エラーフックが実行されました。 |
| `upload_rejected` | アップロード | 上流呼び出し前に、ファイル欠落または想定内の GPX 処理エラーで拒否しました。 |
| `upload_received` | アップロード | ファイルを受信しました。検証はまだ完了していません。 |
| `anemochore_upload_completed` | アップロード | 上流アップロードの応答、または通信エラーを記録しました。 |
| `gpx_stored` | アップロード | アップロード処理で保存結果を記録しました。すべてのローカル拒否や想定外エラーで出力されるわけではありません。 |
| `normalize_rejected` | 正規化 | 必須のファイルがありません。 |
| `normalize_requested` | 正規化 | ローカル処理用のファイルを受信しました。 |
| `normalize_completed` | 正規化 | 正規化した XML の準備が完了したか、想定内の GPX 処理エラーが発生しました。 |
| `gpx_retrieval_requested` | GPX・共有ページ | 取得または共有ページの処理を開始しました。共有キャッシュへのヒットも含みます。 |
| `anemochore_gpx_fetched` | 正規化データ取得 | 上流からの正規化データ取得と検証が成功したか、分類可能な取得エラーが発生しました。キャッシュヒット、処理中の共有ページ生成を待つリクエスト、ローカルで不正と判定した ID では出力しません。 |
| `gpx_retrieval_failed` | 取得エラーハンドラー | 公開 ID が不正、または取得・共有ページで想定外のエラーが発生しました。 |
| `gpx_deletion_requested` | GPX | トークン検証前に削除処理を開始しました。 |
| `gpx_deletion_rejected` | GPX | トークン欠落、またはトークン・ID 検証の結果として拒否しました。 |
| `anemochore_gpx_deleted` | GPX | 上流削除の応答、または通信エラーを記録しました。 |

## 失敗の分類

`failure_reason` は任意フィールドであり、すべての失敗イベントに付くわけではありません。現在の値は以下のとおりです。

| `failure_reason` | 条件 |
| --- | --- |
| `anemochore_rejected` | アップロード・削除のステータスが失敗扱い（400 以上）、または取得のステータスが 200・404 以外（リダイレクトを含む）。 |
| `anemochore_unreachable` | アップロード・削除の通信例外、または取得で応答受信前に発生したネットワーク障害。 |
| `anemochore_invalid_response` | アップロード応答を JSON として解析できたものの、truthy な `id` または `delete_key` がない。不正なアップロード応答すべてをまとめた分類ではありません。 |
| `invalid_id` | 公開取得・共有ページの ID がローカルの検証を通らない。 |
| `not_found` | 上流の取得応答が 404。 |
| `timeout` | 正規化データ取得で、応答・本文の受信期限である 10 秒を超過。 |
| `body_read` | 正規化データの応答本文を読み取れない。 |
| `utf8` | 正規化データの応答本文が有効な UTF-8 ではない。 |
| `json` | 正規化データの応答本文が有効な JSON ではない。 |
| `resource` | 正規化データの応答がバイト数・件数などのリソース制限を超過。 |
| `schema` | 取得した正規化ドキュメントがスキーマ検証を通らない。 |
| `retrieval_internal` | 取得・共有ページの想定外エラーをローカルで HTTP 500 として処理。 |

## 機密情報

通常の監査ペイロードには、サービス API キー、`XYLEM_DELETE_SECRET`、削除キー・トークン、アップロード本文、上流の応答本文を意図的に含めていません。一方、リクエストパス、GPX ID、取得できたクライアント IP、User-Agent 情報は含みます。User-Agent のバイト列は必要に応じて（`%` 自体も含めて）パーセントエンコードし、エンコード単位を分断せず最大 512 バイトに切り詰めます。元のバイト列の SHA-256 ハッシュ、元のバイト長、切り詰めの有無も記録します。

すべてのログに機密情報が含まれないという保証はありません。ロガーには汎用的な秘匿化設定がありません。アップロード・削除の通信エラーは例外メッセージと、存在すればエラーコードを保持し、監査のエラーフックも例外メッセージを記録する場合があります。また、グローバルエラーハンドラーは未処理のエラーを別途標準エラー出力に書き込みます。GPX 処理と取得処理は一部の任意エラーを汎用メッセージに置き換えますが、あらゆる情報の除去を保証するものではありません。URL、パス、User-Agent ヘッダーに秘密情報を含めず、収集したログは機密情報を含む可能性があるものとして扱ってください。ログのアクセス・保存期間・収集方針は運用者が定める必要があります。
